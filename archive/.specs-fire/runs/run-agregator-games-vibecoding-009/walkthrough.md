# Implementation Walkthrough: Безопасная Telegram-привязка и доступ бота

## Summary

Telegram account access now has one owner key: the Telegram user ID stored in `ExternalIdentity`. Group chat IDs can no longer select an account, unlink immediately revokes bot access, and an unconfigured official Telegram Login is represented as a safe unavailable state instead of an internal server error.

## Structure Overview

The bot supplies both the Telegram user ID and chat ID to Laravel. Laravel checks that this is a personal chat, resolves the common account only through the external identity, and keeps the chat ID solely for delivery. The website reads a non-secret OIDC readiness flag to decide whether to show the official-login action.

## Security Considerations

| Concern | Approach |
|---------|----------|
| Group chat account takeover | Backend rejects a chat ID that differs from Telegram user ID. |
| Stale bot access after unlink | Identity, delivery fields and pending codes are removed atomically. |
| Missing OIDC configuration | Public 503 response contains no internal detail or secret. |
| Existing group routes | One-way migration disables delivery without guessing account ownership. |

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Account key | External Telegram identity only | Group chat IDs are shared. |
| Legacy deep-link | Retained temporarily but sends user ID | Avoids breaking active linking while official OIDC remains externally unconfigured. |
| OIDC UI | Readiness-gated | Prevents a guaranteed 500/failed popup. |
