# Design: Избранное и настройка алертов

## Summary

Настройки пользователя отделяются от общих цен игры: у favorite появится один алерт с целью и набором разрешённых сочетаний площадки и вида предложения. Цены продолжают принадлежать canonical Game, поэтому будущая синхронизация сайта и Telegram не дублирует рыночные данные.

## Scope

**In Scope:** миграции, API и минимальная UI-настройка favorite/alert/scopes; безопасный backfill старых favorites; lifecycle active/triggered/rearm.

**Out of Scope:** вычисление срабатывания, Telegram delivery, account merge и процентные алерты.

## Key Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Alert model | `favorite_alerts` one-to-one with Favorite | Одна цель на игру, отдельный lifecycle. |
| Scopes | `favorite_alert_scopes` (source, offer_kind) | Явно выражает выбранные комбинации. |
| Default | Steam official only for migrated data; new UI may select market key/gift | Не превращает legacy favorites в неявные market alerts. |
| States | active, triggered; rearm endpoint | Ясная идемпотентная модель для будущего delivery. |
| Condition extensibility | `condition_type`, `target_value` | Позволяет future `discount_percent` без новой схемы. |
| Client prices | Reject `last_steam_price_rub` | Цены принадлежат canonical refresh pipeline. |

## Technical Approach

```text
Favorite -> FavoriteAlert(target_price, condition_type, status)
                -> FavoriteAlertScope(source, offer_kind)
GET/POST/PATCH favorite -> validated settings -> canonical game remains unchanged
```

### API Changes

- `POST/PATCH /api/me/favorites` accepts `alert` with target and scopes, not user-supplied prices.
- `POST /api/me/favorites/{appid}/alert/rearm` restores active state.

### Database Changes

```sql
favorite_alerts: favorite_id unique, condition_type, target_value, status, triggered_at
favorite_alert_scopes: favorite_alert_id, source, offer_kind unique
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Empty/invalid scope | High | Request validation and DB constraints. |
| Legacy favorite loss | High | Steam official backfill. |
| Source-kind mismatch | High | Whitelist Steam/official and market kinds only. |
| Scope changes affect refresh demand | Medium | Only persist scopes now; demand integration follows alert evaluation/settings work. |
