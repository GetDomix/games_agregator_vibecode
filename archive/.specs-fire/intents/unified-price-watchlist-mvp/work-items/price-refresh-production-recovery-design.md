# Design: Production scheduler и заполнение цен

## Summary

Разделить HTTP API, Laravel scheduler и queue worker на отдельные production процессы. Новая игра продолжает сначала проходить Steam, а после подтверждённого релиза получает source states Plati/GGsel для асинхронного обновления.

## Scope

**In Scope:**

- Docker Compose процессы scheduler/worker.
- Создание market states после Steam release.
- Автоматические тесты очереди, released/announced поведения и stored card.
- Безопасная production verification без секретов и обхода лимитов.

**Out of Scope:**

- Новые ценовые источники, изменение частоты 3 часа/24 часа.
- Синхронное чтение магазинов из search/card HTTP endpoint.
- Pro/квоты, OIDC и устранение дубликатов сообщений бота.

## Key Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Scheduler ownership | Один Compose service `scheduler` с `schedule:work` | Не допускает параллельных владельцев расписания. |
| Queue execution | Один `queue-worker` с queues `prices,default` | Jobs перестают оставаться в PostgreSQL database queue. |
| Unknown game | Только Steam до известного release status | Выполняет запрет marketplace запросов к announced играм. |
| Release transition | `firstOrCreate` states Plati/GGsel, pending now | Existing `whereIn` не создаёт отсутствующие states. |
| Dispatch timing | Scheduler picks pending market states within minute | Сохраняет один централизованный путь очереди. |
| Deploy proof | Compose config + health/process/freshness smoke check | Проверяет реальное выполнение, а не только сборку образа. |

## Technical Approach

```
HTTP search/card -> stored prices only
                        |
Laravel scheduler -> prices:dispatch-due -> database queue -> queue-worker
                                                    |
                                               Steam refresh
                                                    |
                                  released? create Plati/GGsel pending states
                                                    |
                              next scheduler tick -> marketplace refresh jobs
```

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Worker crash | High | Compose restart policy and isolated process health inspection. |
| Scheduler duplicate | Medium | One declared service, Laravel `withoutOverlapping` and `onOneServer`. |
| Marketplace load after release | Medium | Existing rate limits/backoff; scheduler batch limit retained. |
| Steam metadata is wrong | Medium | No market state for announced; transition only follows adapter release status. |
